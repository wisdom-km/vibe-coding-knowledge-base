# 教训：先完成再完美，专业领域是下一场地图修订

**来源**：[DirectorDesk / mira_new](../projects/mira_new/) 2026-08-21 讨论  
**适用**：主路径已经能跑、开始想「做成专业软件」的 vibe coding 项目

## 模式

「先完成再完美」和「做成专业领域软件」不是两条对立路线，是同一条路上的两段：

1. **完成**：用户五步走得通。接缝在，房间可以空。模块数可以锁。  
2. **完美 / 专业化**：只沿着**已经活下来的名词**和**已经在痛的接缝**长，不沿着 Maya / Unreal / 某篇架构文的目录长。

专业化 = 修订产品地图后再改代码，不是另起一套「专业架构」把 Demo 推倒。

## 专业领域该重构什么（按是否已有接缝）

对「导演台」这类工具，专业软件常见能力要拆开看：

| 专业能力 | 何时才算到点 | 正确姿势 | 错误姿势 |
|----------|----------------|----------|----------|
| Undo/Redo | 用户开始因误操作丢布局 | 启用已有 Command 值对象 | 在各面板本地做历史栈 |
| 编排层变薄 | visit 已不敢改 | App **内**分文件，不新建领域库 | 为整洁再拆第 14 个模块 |
| 选择/焦点模型 | 剧本、场景、画布抢焦点 | 显式「当前选择」快照字段 | 每个面板私藏一份选中 |
| 时间轴 / 关键帧 | `00` 用户路径真的变成「时间」 | 先改愿景，再开模块 | Demo 里顺手做动画 |
| 插件 / 脚本 | 第三方要在不改主干的情况下扩展 | 新接缝 + 开关，一个参考插件 | 空插件框架等三年 |
| 多用户 / 云同步 | 真有团队同时改工程 | 新限界上下文 | 把 `.ddproj` 直接丢对象存储当同步 |
| 换渲染器 / DCC 级视口 | 一种后端不够 | 已有 `IRenderer` 第二实现 | 业务头文件出现 GPU 类型 |

原则：**专业是领域变深，不是工具变全。** 导演台的专业是「剧本—机位—画布—导出」更深，不是变成通用 3D 套件。

## 反模式

- 完成之后用「专业人士清单」一次性重写  
- 把专业软件的模块图抄进 Demo（过早房间）  
- 边听建议边让 AI 改代码，地图不改（聊天再次覆盖仓库）  
- 完美被理解成拆更多文件夹  

## 检验问题

1. 这条专业能力服务的是哪条已存在的用户路径？  
2. 它是启用旧接缝，还是必须先改 `00`？  
3. 不做它，主路径是否仍然成立？若成立，可以再等一个真实痛点。
