# 教训：锁死 IA 骨架，只在槽位里优化

**来源**：[DirectorDesk / mira_new](../projects/mira_new/)  
**适用**：主路径已能跑、开始「做成专业工具」的桌面/工作站产品  
**配套**：先读 [ia-philosophy.md](ia-philosophy.md)，填 [ia-skeleton.md](../docs/templates/ia-skeleton.md)

## 模式

代码模块（Script / Scene / UI）回答「逻辑放哪」。  
**IA 槽位回答「屏幕上放哪」。** 两套地图都要锁，不要混成一句「重构 UI」。

锁骨架 = 写下且当作红线：

1. 默认主舞台只许一个  
2. 系统只有一种当前选择（类型可多，实例只有一个）  
3. 槽位名字永久固定，新功能只能进某个槽，不许第八个对等主区域  
4. 工作区 2～3 个：换的是哪些槽显示和工具条，chrome 不换  
5. 每个工作区只留一个主按钮  

主路径以后可以改「先写剧本还是先摆模型」，**槽位和选择模型不要每周改。**

## 然后只在骨架里优化

每次改动先问：它进哪个槽？改的是选中、工具还是主舞台？

| 判定 | 做 | 不做 |
|------|----|------|
| 进得了槽 | 控件、文案、密度、空状态、默认 dock 比例 | — |
| 要再开一个中心窗口 | — | 先改宪法 |
| 同一件事出现在两个槽 | 删到一个主入口（检查器 **或** 视口 gizmo） | 三处都能改 |

实践顺序：

1. **只搬家**：现有面板塞进槽位，功能零新增  
2. **统一选择**：点哪里都更新检查器  
3. **减入口**：重复按钮合并，每模式一个主 CTA  
4. **最后才换皮**：颜色、间距、图标  

## Vibe coding 下单法

好：「只改 RIGHT_INSPECTOR，不要动 CENTER_STAGE。」  
坏：「整体更专业一点。」

Agent 没有槽位宪法时，会把每个功能做成对等 ImGui 窗口——这正是 Demo 乱的来源。

## 与模块落点的关系

| 用户动作 | 代码落点（产品 `07`） | IA 槽 |
|----------|----------------------|--------|
| 看见 / 点击 | UI Panel | 某个槽里的面板，不是新主舞台 |
| 改剧本文本 | Script | 选中 Shot 时检查器或专用次槽，不是第二个中心 |
| 改节点变换 | Scene | RIGHT_INSPECTOR（主）或视口 gizmo（二选一为主） |
| 分镜总览 | Storyboard | BOTTOM_STRIP 或「审片」工作区的主舞台，不可与视口长期并排抢中间 |

## 反模式

功能零搬家、先换皮肤；每来一个模式就新 Dock 成第四个主角；检查器不认统一选择。
