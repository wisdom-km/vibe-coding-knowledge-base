# 教训：专业领域的 IA 哲学

**来源**：[DirectorDesk / mira_new](../projects/mira_new/) 2026-08-21  
**适用**：任何功能已经堆起来、但「看起来不专业 / 不知道当前在干什么」的工具型产品

## IA 是什么

**IA = Information Architecture（信息架构）。**

它不决定好不好看，而决定：

- 东西放哪
- 叫什么
- 用户怎么找到
- 一次只处理哪一层信息

和常混的几件事分开：

| | 管什么 | 不管什么 |
|--|--------|----------|
| **视觉** | 颜色、圆角、图标 | 用户先干什么 |
| **交互** | 拖拽、快捷键手感 | 信息分成几块 |
| **功能** | 能不能导出、能不能关联 | 按钮该不该出现在这里 |
| **IA** | 有哪些区域、谁是主舞台、选中是什么、名字怎么叫 | 像素级美化 |

Photoshop 花、Premiere 像时间线、Blender 像视口——皮肤不同，**骨架很像**。专业感来自减少并列的主角，不是增加面板。

## 六条反复出现的组织原则

几乎所有 DCC / 后期软件都遵守。借鉴的是组织法，不是把面板画成某软件的样子。

1. **一次一个主舞台**  
   PS 是画布，PR 是监视器+时间线，Blender 是 3D 视口。辅助可以很多，不能再有第二个主角。

2. **一次一种选中**  
   选中之后，右边只编辑这个东西。禁止「这里改模型、那里改镜头、菜单里再改一次」。

3. **空间按职责分区，不按功能堆砌**  
   左：有什么。中：正在看什么。右：正在改什么。下：序列/时间/分镜。上：模式和全局命令。

4. **模式切换，而不是新窗口爆炸**  
   同一套外壳，内容换班。不要每来一个功能就新开一个对等大面板。

5. **名字稳定，层级浅**  
   「检查器」「资源」「镜头」全程不变。用户靠名称导航，不靠记临时窗口。

6. **进阶藏起来，主路径外露**  
   默认只露当前模式需要的 5～8 个入口。其余进菜单或检查器折叠。

## 如何快速入门

不要先学视觉规范。用三个问题面试自己的 Demo：

1. 打开软件，**中间那块**默认是什么？若答不出或答「好几个窗口」，IA 没锁。  
2. 点一下某处，**右边**是不是只在编辑这一处？若两套高亮各干各的，选中模型没锁。  
3. 新功能来了，你是**塞进已有槽**还是**再开一个对等窗**？后者就是 Demo 思维。

对照：

- **Demo 思维**：有剧本 → 开剧本窗；有资源 → 开资源窗；有画布 → 再占一块中间。  
- **IA 思维**：用户永远在「看主舞台 + 改选中项」。剧本是一种选中（Shot），资源是往层级里加东西的入口，画布是底条上的镜头序列。

入门作业：填一张 [IA 骨架表](../docs/templates/ia-skeleton.md)，当作不能每周改的宪法。然后才谈换皮。

## 如何执行（锁死骨架，只在骨架里优化）

见 [lock-ia-skeleton.md](lock-ia-skeleton.md)。一句话：先写槽位和选择模型，再搬家、减入口，最后才颜色图标。Vibe coding 按槽位下单，禁止说「整体更专业一点」。

## 反模式

- 用功能清单当 IA（有多少能力就开多少对等窗）  
- 把 Photoshop 的历史记录面板画过来当「专业」  
- IA 未锁就开始换主题色  
- 同一件事在三个槽都能改，还全留着
