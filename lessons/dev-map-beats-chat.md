# 聊天为什么靠不住

Cursor、Claude、Grok 来回接力、项目又不是一个周末能扔的，几乎都会碰到这件事。

Vibe coding 的记忆住在对话里。对话一结束，架构就像没发生过。对抗办法不复杂，但要真写进仓库：

一份开发地图，愿景、边界、路线、现状、规范都在里面。  
给 Agent 的 Prompt 只规定工作方式，别把容易变的技术细节再抄一份进去。  
每次干完，更新「现在进行到哪」。  
能用构建系统拦住的错误依赖，就别只靠 Prompt 提醒。CMake 比记忆硬。

DirectorDesk 的落地是 `docs/dev-map` 那一套，根目录 `AGENTS.md` 只指向它，不复制正文。

常见翻车：把整份架构粘进 Cursor Rule，改地图时忘了改 Rule；拿上一场聊天当需求，和仓库现状对着干；现状文件不更新，下一场 AI 从零开始发明架构。

检验很简单。新开一场对话，不贴聊天记录，只 clone 仓库。它知不知道现在该做什么、不该做什么？不知道，就还没沉淀。
