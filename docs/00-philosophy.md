# 知识沉淀哲学

## 为什么要做这个知识库？

在 Vibe Coding 中，AI 生成速度极快，但人类的**判断力、决策路径、失败教训**才是真正的稀缺资产。

如果只依赖聊天记录或脑子记忆，这些资产会快速衰减。  
本仓库的核心原则是：

> **把「阶段」作为最小可沉淀单元。**

每个有价值的项目阶段，都应该留下一份结构化记录。

---

## 五个核心原则

1. **过程 > 结果**  
   记录「为什么当时这样决策」，比记录最终代码更重要。

2. **失败优先**  
   踩坑记录的价值通常高于成功案例。真实的失败 + 复盘，才是最好的老师。

3. **可复用性**  
   写完后问自己：「这个经验能不能帮到三个月后的自己，或别人？」如果不能，就再提炼一次。

4. **小而完整**  
   一次只记录一个阶段。不要试图写「整个项目回顾」。

5. **时间戳 + 上下文**  
   永远写清楚当时使用的工具版本、模型、项目约束。否则经验会快速过时。

---

## 与 Vibe Coding 的对齐

Vibe Coding 的危险之处在于「感觉很好，但没有沉淀」。  
本知识库强制把「感觉」变成「可检查的记录」。

当你下次再遇到类似问题，你不是从零开始，而是从「之前已经验证过的经验」开始。
