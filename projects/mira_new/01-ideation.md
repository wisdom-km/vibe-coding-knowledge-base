# 阶段记录：Ideation

**项目名称**：DirectorDesk（mira_new）  
**阶段**：Ideation  
**日期**：2026-08-18  
**工具与模型**：Cursor Agent 多轮对话；产品负责人 Wisdom  
**项目当前约束**：一个人 + AI；Windows 优先；要开源；目标用户是不会 3D 软件的创作者

---

## 1. 这个阶段的目标是什么？

把「普通人做可控 AI 视频」收成一条永不偏离的用户路径，并写进仓库，而不是留在聊天里。

路径后来锁在 `docs/dev-map/00`：

1. 写 Markdown 剧本  
2. 从资源库拿角色和场景  
3. 用预设机位摆镜头  
4. 在分镜画布总览  
5. 导出参考图，以后再接文生图/视频  

## 2. 我给 AI 的核心提示词 / 上下文

没有靠一句「帮我做一个 3D 软件」。先逼出宪法：P0 只做哪些、明确不做哪些、许可证、平台。

有效约束包括：

- 优先用本地资源走通闭环，再补在线库
- 不做时间轴、Undo、自由画布、真 AI SDK
- 代码 MIT，官方资产 CC0
- Linux 不进 P0

完整工作方式后来收成产品仓库的 `06-CURSOR-WORKING-PROMPT.md`。可复用摘录见本知识库 `prompts/architecture/dev-map-first.md`。

## 3. 实际发生了什么？

- 好：先有「导演台」隐喻，模块名词自然长出来（剧本、机位、画布、导出），而不是先选 bgfx 再找产品。
- 翻车风险：若先让 AI 搭「通用 3D 编辑器」，会立刻滑向骨骼、材质、时间轴——全是 `00` 红线。
- 人工干预：把「连接剧本与 AI 视频的可视化中间层」写成最高优先级；任何炫技功能若打断闭环就砍。

## 4. 关键决策与取舍

| 决策点 | 当时为什么这样选 | 事后看是否正确 |
|--------|------------------|----------------|
| 产品是导演台不是建模器 | 目标用户没有 3D 能力 | 正确。预设机位降低门槛 |
| 剧本用 Markdown | 创作者已会写；可测可 diff | 正确。Parser + 中文路径测试撑住 |
| 先本地后在线 | 随时中断也要能跑完主路径 | 正确。Phase 7 才算 0-1 |
| 开源 Open Core | 引擎开源，资产与 AI 以后商业化 | 目前成立；AI 仍冻结 |

## 5. 踩坑与惊喜

**踩坑**：把「以后要接 AI 视频」说太早，模型会想立刻接供应商。必须写成：P0 只留接口。

**惊喜**：用户路径一旦写成宪法，后面 Phase 顺序几乎自动排出来。

## 6. 可复用的经验

Vibe coding 的第一步不是打开编辑器，是把**主路径 + 红线**提交进仓库。没有这两样，AI 会用训练数据里的「完整 3D 套件」填满你的 Demo。

## 7. 给未来自己的一句话

先问「用户五步走完没有」，再问「要不要再加一个 3D 功能」。
