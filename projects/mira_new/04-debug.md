把「能编译」升级成「能给别人装、能给别人看懂架构」，并留下可复查的修复，而不是口头说修了。

## 2. 我给 AI 的核心提示词 / 上下文

对渲染类 bug：先假设接缝被穿透（UI 或 Storyboard 直接打到 bgfx 帧图），再看主循环是否在一帧里多 `bgfx::frame()`。

对包装类 bug：先看 CI/本机工具链实际装了什么语言包，不要假设 Inno 带中文 isl。

## 3. 实际发生了什么？

下列坑都有 commit 或源码对应，不是事后编的。

### 坑 1：滚轮缩放视口闪黑/闪空帧

**现象**：在 3D 视口滚轮时画面闪。  
**根因**（`4323b4e`）：缩略图为了拿 320×180 图去 `bgfx::reset`，并在主循环里同步回读，额外的 `bgfx::frame()` 把刚清空的交换链呈上去。视口窗口还把滚轮当成 ImGui 滚动条。  
**修复**：

- `IRenderer` 增加 `RequestReadback` / `HasPendingReadback` / `TakeReadback`，缩略图异步回读
- 视口用 InvisibleButton 吃输入；尺寸抖动小于 2px 不重建 RT
- 离屏导出仍走原来的同步回读接缝，不截 UI

**教训**：第二调用方（缩略图）不能破坏第一调用方（交互视口）的帧图。异步是接缝，不是「再开一条线程改 Renderer」。

### 坑 2：Windows 安装包编不出中文向导

**现象**：`ae5284c`。winget 的 Inno Setup 6 **不带** `ChineseSimplified.isl`。  
**修复**：安装向导改用 Inno 默认语言；**应用内 UI 仍是中文**。不要为包装器去仓库里塞一份 isl 然后在别人机器上失败。  
**教训**：包装工具链 ≠ 产品 i18n。验证要用实际安装器包，不是用「我本机有中文 isl」。

### 坑 3：GitHub 上看不见架构图 / 图画出来是扁的

**现象**：README 里 Mermaid 不能缩放；后来做了 `architecture.html`，SVG 被 CSS `max-width` 挤没。  
**修复**：GitHub Pages 交互图；`sizeSvg()` 用 viewBox 写死像素宽高（`af501ce`）。目录页一度按 08→00 倒序，改回 00→08。  
**教训**：GitHub 渲染 ≠ 你的知识呈现。给架构单独做查看器，正文仍只在 `docs/dev-map`。

### 坑 4：中文路径

**预防性坑**：目标用户是中文环境。`Platform::Paths` 用 `std::filesystem::u8path` 和 Win32 宽字符转换，业务模块禁止 `_wfopen`。测试必须包含非 ASCII 文件名。  
**教训**：编码转换是模块边界，不是每个 loader 自己来一套。

### 坑 5：Shader 二进制

**纪律**：`shaders/*.sc` 进仓库；shaderc 构建期编译；不提交生成物。否则 Windows/macOS 后端立刻分叉。

### 坑 6：macOS 只存在于 CI

**阻塞**：本机无 Mac。P0 接受「CI 绿 = 门禁」，实机回归仍欠着。不要假装已经在 Mac 上点过一遍。

### 坑 7：AI 空岛被当成半成品

**现象**：`src/AI` 有 Mock，grep `Application.cpp` 没有 AI 符号。  
**处理**：冻结，不接线、不删库、不往里堆供应商。这是「接缝在、房间空」。往里填才是灾难。

## 4. 关键决策与取舍

| 决策点 | 当时为什么这样选 | 事后看是否正确 |
|--------|------------------|----------------|
| 闪屏修在 Renderer 契约 + App 调度 | 不让 Storyboard 认识 bgfx | 正确 |
