# 架构怎么选

2026-08-18。地图 `00` 到 `06` 已经在仓库里。接下来不是选「最专业的架构」，是选一条人走得动、AI 也忘不掉的路。

我们走的是单仓、按职责拆模块、第三方关在 backends。不是微服务，也不是一个 `main.cpp` 通吃。

UI 只链 Core 和 imgui，面板只发 Command、只读一份快照。渲染走 `IRenderer`，模型走 `IModelLoader`，下载走 `IHttpClient`。剧本归 Script，节点归 Scene，绑定归 Link，App 负责组装。CMake 比 Prompt 硬：UI 链不上 GLFW 和 bgfx。

Phase 1 就把离屏回读做掉，因为视口和导出是两个调用方，这条缝不先打，后面缩略图会把 bgfx 拖进分镜模块。OBJ 和 GLB 并存，才抽加载器注册表，而不是在资源面板里堆 `if`。

故意没做的：为三年后每个按钮建空房间；功能开关平台；把十三个库再拆成十三个进程；在 P0 实现 Undo（Command 先留着当接缝）。AI 模块有 Null 和 Mock，App 至今没接线——空岛冻结，不是半成品愧疚。

P0 结束后正确的收敛是锁模块数，不是继续拆。短命分支 `cursor/phase-4-camera-presets` 打乱过「默认在 main 上工作」的纪律，tag 也不干净。那是过程问题，不是技术问题。

交付物应该是宪法、模块怎么依赖、有验收的 Phase、以及一份不复制技术细节的 Agent 工作方式。不该交付假想功能清单。功能可以没有，接缝得先有；有了之后，别为想象建房间。
