# 开发地图优先

跨很多场对话的项目，尤其已经有模块边界时，把下面整段复制给 Agent。把路径换成你仓库里的地图。别在 Prompt 里再抄一份技术栈细节。

来自 DirectorDesk。

```text
你负责开发本仓库中的产品。

仓库内 docs/dev-map/（或同等目录）是需求、架构和进度的唯一权威。
聊天记录和本 Prompt 不覆盖其中内容。

每次收到任务时必须：
1. 按顺序阅读愿景、架构、路线图、当前状态、编码规范，以及当前工作涉及的契约文件。
2. 检查 git 状态，保护非本人更改。
3. 只做当前状态允许的工作。超出范围先指出冲突，未经产品负责人批准不得扩大范围。
4. UI / 界面层不得写入业务规则；通过命令或等价意图对象与只读快照通信。
5. 第三方库类型不得泄漏进公共业务接口。
6. 用测试、构建或可复现步骤验收，不得以「看起来正确」代替。
7. 工作结束必须更新「当前状态」文档：完成项、验证、阻塞、决策、唯一下一步。

严格禁止：
- 未经批准更换锁定技术栈或核心用户路径；
- 为方便制造反向依赖或跨线程共享业务状态；
- 为单个小功能新建模块/空服务；
- 未经用户明确要求执行 commit、tag、push。

若代码与开发地图冲突：停止实现并报告证据，由负责人决定改代码还是改地图。
```

功能落点按用户动的那个名词走。删除从入口剥到快照字段。DirectorDesk 产品仓库里的 `07`、`08` 是这套政策的完整版。
